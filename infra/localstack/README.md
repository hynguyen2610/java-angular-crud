# Local deployment: LocalStack + Docker Desktop Kubernetes

Deploys the app to the local Docker Desktop cluster, with the AWS-shaped parts in
LocalStack community (installed from [k8s/localstack/values.yaml](../../k8s/localstack/values.yaml)).

| Piece | Where it runs | Notes |
|---|---|---|
| Angular build | S3 static website in LocalStack | uploaded by Terraform from `frontend/dist` |
| Secrets (JWT, DB, admin) | Secrets Manager in LocalStack | generated by Terraform, mirrored into a Kubernetes secret |
| Spring Boot backend | Deployment in `product-manager` | image built on the host |
| Postgres 16 | StatefulSet with a 1Gi volume | |
| `edge` nginx | Deployment | same-origin entry: `/` → S3 website, `/api`, `/ws`, `/actuator/health` → backend |

ECS, RDS, ECR and CloudFront are LocalStack Pro features, so those roles are played
by the cluster. Docker Desktop's nodes pull images straight from the host image
store, so no registry is needed.

## Deploy

```powershell
docker build -t product-manager-backend:local backend
cd frontend; npm run build; cd ..

# Terraform talks to LocalStack through this port-forward; keep it open while applying.
kubectl -n localstack port-forward svc/localstack 4566:4566

cd infra/localstack
terraform init
terraform apply
```

## Use

```powershell
kubectl -n product-manager port-forward svc/edge 4200:80
terraform output -raw admin_password
```

Open http://localhost:4200 and sign in as `admin` with that password.

## Redeploy

- Frontend: rebuild, then `terraform apply` uploads changed files.
- Backend: build with a new tag and pass it, so the Deployment rolls:
  `terraform apply -var backend_image=product-manager-backend:<new-tag>`.

## Caveats

- LocalStack community keeps no state: if its pod restarts, the bucket and secret are
  gone. Run `terraform apply` again to recreate them (Postgres data is kept).
- Terraform state holds the generated secrets in plain text; it is git-ignored, keep it local.
